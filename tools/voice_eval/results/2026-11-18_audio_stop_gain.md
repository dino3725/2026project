# 2026-11-18 소음이 섞인 정지 녹음 분석과 선택적 음량 보완

## 입력 정답에 대한 정정

사용자는 CUEVO5 시험에서 스톱/멈춰/정지를 각 3회 순서대로 말했다고 확인했습니다.
그러나 두 번째 스톱으로 순서 대응했던 `vad_command_20261117_225525_002.wav`를
다시 들은 뒤에는 ‘너무 작거나 불분명해서 판단하기 어려움’이라고 답했습니다.
따라서 **그 WAV 자체가 두 번째 스톱이라는 확정 라벨은 붙이지 않습니다.**

원래 실시간 시험의 오디오 7/9·전사문 포함 8/9라는 사용자 요청 대비 관찰 결과는
유지합니다. 다만 실패를 해당 WAV의 인식 문제로 한정할 수 없습니다. 실제 스톱이
VAD에 포착되지 않고 별도의 주변 소음만 저장됐을 가능성도 배제할 수 없습니다.
연속 원음이 없으므로 이 구분은 현재 자료로 해결하지 못했습니다. 추가 녹음은 요청하지 않습니다.

새 `audio_stop_noisy_dev_20261118.json`에서는 1·3·6~11번 8개를 확인 가능한 정지로,
12·14·15번을 일반 요청/인사로, 2·4·5·13번을 정답 미확정으로 분리했습니다.
‘감사합니다’ 구간을 실제 소음 또는 STT 환각으로 단정하지 않습니다.

## 실패 파일 탐색

두 실패 후보에 원본/2/4/8배 음량과 시작 자르기 0/150/300/450/600/900ms를 조합하고,
각 조건에서 기존 여섯 입력 위치를 검사했습니다. 파일과 런타임 기본값은 변경하지 않았습니다.

- 2번: 모든 조합에서 KWS 감지 없음. Whisper도 음량 1/2/4/8배에서 모두 빈 결과.
- 3번 ‘어이구 스톱’: 원본 전체 구간은 실패. 2배 음량 전체 구간 또는 150ms 이상
  시작 자르기 후보에서 감지됨. 앞부분을 무조건 잘라 실제 정지를 잃을 수 있는 방식은
  런타임에 넣지 않았습니다.
- 별도 KWS threshold 0.001 및 score 2/4 탐색에서도 2번은 감지되지 않았습니다.
  score 2는 3번을 감지했으나 운영 판단 기준을 바꾸는 대신 PCM 복사본의 제한된
  음량 보완을 선택했습니다. 모델 threshold=0.01, score=1.0은 유지합니다.
- 성공한 1번 RMS 약 322/peak 3673, 불명 2번 약 148/1895, 혼합 3번 약 296/4850
  (PCM16 단위)입니다. 전체 RMS만으로 배경 발화와 정지 발화를 구분하거나 원인을
  확정하지 않습니다. 특히 3번은 단순히 파일 전체 peak가 작아서 실패했다고 볼 수 없습니다.

## 구현

`audio_stop.recheck_gain`을 추가했습니다. **기본 1.0(추가 증폭 없음)**,
실험 후보 2.0이며 허용 범위는 1~4입니다.

1. 원본 PCM을 새 스트림에서 먼저 1회 검사하고 성공하면 즉시 반환합니다.
2. 실패하고 gain>1이면 KWS용 복사본만 증폭해 검사합니다.
3. phase_shifts=true면 증폭 복사본에 기존 0/120/300/240/180/60ms 위치를 적용합니다.
   gain=1이면 이전 위치 보완과 동일합니다.
4. 증폭 상한을 실제 peak로 제한해 PCM 포화/부호 뒤집힘을 방지합니다. 무음과 이미
   최대 크기인 PCM은 그대로 둡니다. 발화 길이와 이벤트의 원래 좌표는 유지합니다.
5. 모든 시도에 원래 VAD 종료 후 0.5초 제한을 공유합니다. 늦은 결과는 버립니다.

STT·화자 인증·연속 KWS에 들어가는 원본과 저장 WAV는 바꾸지 않습니다.
stop의 화자 인증 예외, LLM 우회, 기존 중복 억제와 fetch 차단은 유지합니다.
기본 mode=off/phase_shifts=false/gain=1.0입니다. Jetson/공유 메시지/음성 분류기 프롬프트를
변경하지 않았고 실제 ROS 발행·로봇·마이크 실행은 하지 않았습니다.

## 개발 비교

기존 manifest 126개 + 최신 15개 = 141개 분리 파일입니다. 정지 57개, 일반 음성 78개,
범위 밖 정지 1개, 미확정 5개로 나누었습니다. 최신 2번을 성능 분모에서 제외한 이유는
앞의 사용자 청취 확인이며, 이 제외를 실제 9회 시험 통과로 바꾸어 해석하지 않습니다.

|---|---:|---:|
| 확인 가능한 정지 57개 | 56/57 | 57/57 |
| 일반 음성 78개 | 오탐 0/78 | 오탐 0/78 |
| 미확정 5개 | 감지 0 | 감지 0 |

이는 시간 제한 없는 개발 비교입니다. 기존 감지의 회귀는 없고 최신 3번만 추가 복구했습니다.
원래 자료와 후보 선택에 사용한 자료이므로 독립 검증 정확도가 아닙니다.
미확정 입력은 정지 미탐/일반 오탐 분모에 포함하지 않았습니다.

실제 수정한 런타임 함수를 다시 실행한 제한 적용 비교에서도 정지 57/57을 감지했습니다.
단독 검사 중앙값 약 42ms, 최대 약 237ms였습니다. 일반 음성의 무제한 검사 중앙값은
약 1.71초이며 0.5초 제한에서는 78개 중 74개가 만료됐습니다. 이 만료를 ‘일반 음성
검사를 모두 끝냈다’고 해석하지 않습니다. 별도의 완주 결과에서 오탐 0/78을 확인했습니다.
미확정 5개는 세 조건 모두 감지 없음입니다. 10초 합성 무음에서도 정지 감지 없음.

## STT·화자 인증과 동시 처리

기존 최신 시험 정지 9개 + 이번 확인 가능한 정지 8개 + 본인 가져오기 2개 + 타인
가져오기 2개를 완성 발화로 주입했습니다. 실제 Whisper/ECAPA/KWS를 사용하며,
IDLE·LLM은 모의이고 명령은 로컬 콜백입니다. 연속 마이크·실제 LLM 워밍업 부하는 아닙니다.

- 원본 1회 기준 보완 13/17, 위치+2배 후보 17/17. 기존 여섯 위치만의 비교와 구분합니다.
- 최종 stop 콜백은 양쪽 17개, 발화당 1회입니다. 개선 전에도 전사문이 놓친 오디오를
  보완하므로 최종 성공 13→17로 해석하지 않습니다.
- 본인 2개 fetch 허용, 타인 2개 speaker_rejected 차단 유지.
- 후보 보완 계산 약 84~475ms, 정지 검사 만료 0. 최신 3번은 약 475ms로
  **0.5초 제한에 가까워 여유가 작습니다.** 실제 LLM cold warmup에서도 성공한다고
  주장하지 않습니다. 비정지 4개는 후보에서 모두 재검사 만료였습니다.
- STT 시간은 원본 1회 조건 정지 약 1.77~2.06초, 후보 약 1.84~2.22초입니다.
  순차 실행한 개발 비교로 인과를 확정하지 않으며 추가 CPU 비용을 숨기지 않습니다.

## 입력 위치 반복 검사와 연속 재생

57개 정지 파일 앞에 0/60/120/180/240/300ms 무음을 각각 붙인 342회 검사에서
원본 1회는 321/342, 후보는 무제한과 0.5초 제한 모두 342/342였습니다.
제한 적용 계산 최대 약 449ms, 만료 0입니다. 이는 같은 파일의 상관된 반복이며
독립적인 정지 녹음 342개 또는 실시간 인식률을 뜻하지 않습니다.

기존 `stop_probe.oIcb6b/continuous.wav` 50초를 실제 시간 간격으로 VAD/STT/화자 인증/
KWS에 공급했습니다. 스톱 6회·멈춰 3회에 로컬 stop 콜백이 각각 한 번씩 발생했고,
프레임 누락 0·입력 생산 오류 0입니다. 재검사 9개가 모두 감지됐지만 한 건은
약 494ms로 제한에 가까웠습니다. 파일 끝에서 발생한 PCM 종료 오류는 재생 도구가
예상하는 EOF이며 실제 마이크 장애가 아닙니다. ROS 발행과 실제 LLM 실행은 없습니다.
이 녹음은 최신 소음 시험의 연속 원음이 아니므로 그 시험의 불명확한 누락을 설명하지 못합니다.

## 재현

노트북 파일 재생이며 마이크/ROS/Jetson은 필요 없습니다.

```bash
cd ~/2026project
PYTHONPATH=src/voice_command_pkg .venv/bin/python tools/voice_eval/evaluate_audio_stop_phases.py \
  --manifest tools/voice_eval/audio_stop_stability_dev_20261112.json \
  tools/voice_eval/audio_stop_fp32_live_dev_20261112.json \
  tools/voice_eval/audio_stop_phase_dev_20261117.json \
  tools/voice_eval/audio_stop_noisy_dev_20261118.json \
  --recheck-gain 2.0 --output log/audio_stop_gain_repeat.json

PYTHONPATH=src/voice_command_pkg .venv/bin/python tools/voice_eval/check_audio_stop_concurrency.py \
  --manifest tools/voice_eval/audio_stop_phase_dev_20261117.json \
  --extra-manifest tools/voice_eval/audio_stop_noisy_dev_20261118.json \
  --speaker-profile speaker_profiles/owner_ecapa_development.json \
  --recheck-gain 2.0 --output log/audio_stop_gain_concurrent_repeat.json
```

`evaluate_audio_stop_phases`의 original 열은 원본 1회 기준입니다. 위 표의 기존 여섯 위치
기준과 혼동하지 않습니다. gain을 1.0으로 지정하면 이전 위치 보완을 재현할 수 있습니다.
