# 2026-11-12 — 정지 전용 오디오 감지 구현 및 개발 평가

## 결론

공유 PCM 입력 → 별도 키워드 감지 스레드 → 기존 stop 발행 함수 연결을 구현했습니다. 그러나 후보 모델의 운영 채택은 보류하며 `audio_stop.mode: "off"`를 기본값으로 유지합니다. 개발 녹음의 직접 재생에서는 대상 정지 17/22, 50초 연속 녹음에서는 5/9였습니다. 운영과 같은 시작 1.2초 폐기 및 실제 VAD/Whisper 병렬 처리에서는 오디오 감지 3/9, 전사문 경로와 합쳐 8/9였습니다. 느린 다섯 번째 “스톱”의 “슈톡” 오전사 문제는 남습니다.

구현/안전장치 검증과 모델 정확도 채택 여부를 구분합니다. 정지 인식 문제가 해결됐거나 실제 로봇의 종단 정지 지연이 개선됐다고 주장하지 않습니다.

## 구현

- `audio_stop_model.py`: 고정 모델 리비전과 4개 파일 SHA256 검증, 선택 의존성 지연 로딩, CPU 추론 스레드 1개. 실행 중 모델 다운로드나 오디오 외부 전송 없음.
- `audio_stop.py`: 30ms 프레임의 별도 추론 스레드. 대기열 128프레임, 로컬 읽기 시각 기준 최대 나이 0.5초. 과부하 시 대기열 폐기와 모델 문맥 초기화; 추론 중 폐기된 세대의 결과도 무시.
- `pipeline.py`: 마이크는 기존 1개. 초기 안정화 뒤 VAD/RMS 게이트 이전 PCM을 전달. `active`에서만 stop 발행 및 이전/겹친 fetch 무효화. 벽시계와 PCM 위치를 함께 검사하고 발행 잠금 안에서 늦은 LLM fetch 결과를 다시 차단.
- `off`: 기존 전사문 경로만 사용. `shadow`: 새 감지 로그만 기록하며 fetch를 무효화하지 않음. `active`: 기존 publish 콜백을 사용하므로 `publish_commands=false`도 그대로 적용.
- 기존 전사문 정지는 유지. 동일 발화에서 빠른 stop 발행 성공이 확인된 경우만 중복 억제. 발행 실패/dry-run은 전사문 경로를 유지하며 새 stop을 막는 전역 cooldown 없음.
- 모델 누락/변조/추론 오류 시 선택 경로만 비활성화. 종료 후 새 명령 발행 차단. LLM SYSTEM_PROMPT, 공유 인터페이스, Jetson 제어 코드 및 팔 파라미터 변경 없음.
- 단일 발화 `run_once` API는 `off` 전용. 실시간 KWS는 `run_forever`의 연속 스트림에서 사용.
- 별도 모델 다운로드 도구, 파일 단위 평가 도구, 실제 VAD/STT/KWS의 파일→PCM 파이프 재생 도구 추가.

## 모델과 재현 조건

- 모델: [kairess/ko-kws-zipformer-tiny](https://huggingface.co/kairess/ko-kws-zipformer-tiny), Apache-2.0 표기, INT8 한국어 streaming Zipformer 후보. 모델 카드도 잡음/비슷한 발음의 오인식 가능성을 명시합니다.
- 사용 API: [sherpa-onnx Keyword Spotting](https://k2-fsa.github.io/sherpa/onnx/kws/index.html). 임계값과 키워드 가산점의 조합을 개발 데이터로 비교했습니다.
- 리비전: `c2430dd975019802a68077e0fc4dd0521ae193e9`.
- `.venv` 선택 의존성: `sherpa-onnx==2.0.1`, `sherpa-onnx-core==2.0.1`. 개발 시 토큰 확인에 sentencepiece 0.2.3을 사용했지만 실행 의존성에는 필요하지 않습니다.
- 3개 ONNX와 tokens.txt 합계 9,326,495 bytes. 모델/WAV/.venv는 Git에 포함하지 않음.
- 키워드 BPE: `▁ 멈 춰 @멈춰`, `▁정 지 @정지`, `▁스 톱 @스톱`. 고정 토큰을 사용하며 음성 유사어를 임의로 추가하지 않았습니다.
- 실험 후보값: threshold 0.01 / score 1.0 / max_active_paths 4 / trailing blanks 1. 이 값은 운영 승인값이 아닙니다.
- VAD: 시작 0.4, 종료 900ms, 시작 RMS 200, 초기 1200ms 폐기 유지. Whisper: small / cpu / int8 / ko / beam 5 / 빈 힌트 / temperature [0.0].

## 데이터와 채점 범위

모든 자료는 이미 설정 비교에 사용한 **개발 자료**입니다. held-out 평가나 새로운 화자 일반화 검증이 아닙니다. `audio_stop_dev_20261112.json`에 파일별 상대 경로·정답 범주·SHA256을 기록했습니다.

- 기존 순서 확인 27개 + vad_check 8개 + end600 7개 + end750 7개 = 분리 WAV 49개.
- 대상 3단어가 들어간 stop 22개, 비정지 26개, “그만 움직여” 1개. 마지막 문장은 기존 전사문 규칙 대상이며 새 3단어 감지기의 범위 밖으로 따로 기록했습니다.
- 50초 연속 녹음: 평소 속도 스톱 3회, 느린 스톱 3회, 멈춰 3회.
- 직접 재생은 각 파일에서 모델 스트림을 새로 만들고 끝에 합성 무음 0.6초를 붙였습니다. 검출의 합성 끝부분 여부를 JSON에 표시했습니다. 최종 후보의 모든 검출은 원본 오디오 구간 안에 있었습니다.
- 10초 합성 무음은 별도 sanity check입니다. 사용자 보고 생활 소음 30초의 연속 WAV는 없으므로 이번 모델의 실제 생활 소음 오탐률은 검증하지 못했습니다.
- 연속 녹음의 채점 창은 이전 VAD/RMS 음성 구간 추정에서 시작해 말끝 추정 + 최대 1초까지, 다음 발화 시작 전까지로 제한했습니다. 한 검출을 여러 정지에 중복 배정하지 않습니다. 수작업 음소 단위 정답 시각은 아니므로 정밀 말끝 지연 지표로 사용하지 않습니다.

### 50초 연속 녹음과 운영 조건의 차이

직접 재생은 원본 0초부터 모델에 입력했으므로 13.29, 14.88, 22.89, 27.69, 31.53초에 감지했습니다(1·2·5·7·9번째 발화). 기존 Whisper가 “슈톡”으로 읽은 5번째를 이 조건에서는 잡았지만, 이것만으로 운영 문제가 해결됐다고 판단하면 안 됩니다.

실제 코드의 초기 1.2초 폐기를 적용하면 감지는 모델 입력 기준 23.85, 26.73, 28.32초, 즉 원본 기준 25.05, 27.93, 29.52초(6·7·8번째)로 바뀌었습니다. 같은 앞부분을 제거한 빠른 오프라인 재생에서도 동일하게 3회였으므로, 대기열 유실 탓으로 설명할 수 없습니다. 입력 시작 위치/음향 문맥/모델 청크 경계에 민감한 후보라는 근거이며, 구체 내부 원인은 확정하지 않았습니다.

실시간 속도의 파일→파이프→실제 VAD/Whisper/KWS 통합 재생을 2회 확인했습니다. 첫 실험 뒤 저장소 재현 도구로 다시 실행했고 둘 다 아래 결과가 같았습니다. 실제 마이크, ROS 발행자, 로봇, Ollama 요청은 사용하지 않았습니다.

- 로그의 `published=True` / `[ROS] published`는 이 도구의 성공한 **가짜 로컬 콜백**이며 ROS 전달 성공을 의미하지 않습니다. 출력 JSON의 `no_ros_no_microphone=true`로 구분합니다.

## 시간과 부하 측정의 한계

- 분리 49개와 연속 50초, 원본 합계 150.59초. 직접 재생의 모델 처리 경과 시간 합계 6.835초, 최대 단일 입력 호출 0.064초. 끝 합성 무음의 처리도 포함합니다.
- 최종 통합 재생의 `[AUDIO STOP] frame_to_decision`은 약 0.018 / 0.041 / 0.024초. 마지막 프레임을 프로그램이 읽은 뒤 처리한 시간일 뿐, 단어를 말한 뒤의 총 지연이나 로봇 정지 시간은 아닙니다.
- 별도 선행 부하 시험(이전 후보 0.05 / 2.0)에서 50초 실시간 프레임 입력과 Whisper 14회 추론을 겹쳤습니다. 프레임 손실 0, 모델 오류 0이었지만 해당 후보의 감지는 4/9였습니다. 최종 후보 정확도 수치와 섞지 않습니다.
- PulseAudio 실제 버퍼링, Wi-Fi DDS, Jetson 액션 취소/바퀴/팔의 정지 지연은 이번 시험에 없습니다.
