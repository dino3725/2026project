# 2026-11-11 녹음 기반 STT 설정 비교

## 범위와 결론

사용자가 순서대로 녹음했다고 확인한 27개 개발 WAV를 모두 사용했다. 기존 small/CPU/int8/ko,
beam 5와 빈 힌트는 유지하고, **Whisper 재시도 온도 목록만 `[0.0]`으로 변경**한다.
정지 규칙, LLM SYSTEM_PROMPT, VAD, 로봇 상태 게이트, 공유 인터페이스는 바꾸지 않았다.
빠르게 말한 “스톱”의 미감지 문제는 이번 자료만으로 해결됐다고 주장하지 않는다.
저장된 15번은 사용자가 천천히 발음해 성공한 녹음이다. 자연스러운 속도의 실패 음성은
별도 WAV에 없으므로 연속 녹음으로 녹음 시작과 전사를 분리해 확인해야 한다.

## 측정 방법

- production `transcribe_audio`의 메모리 PCM 입력과 같은 경로. 모델 1회 로드·워밍업 제외.
- 문장마다 설정 순서를 교대하며 2회 반복. 일반 27개 × 4설정 × 2회 = 216회,
  1초·3초 합성 무음 × 4설정 × 2회 = 16회. 후속 온도 비교는 각각 108회, 8회.
- 첫 비교 후에 결과를 보고 추가 후보를 탐색했으므로 모두 **개발 평가**다. held-out 재사용 없음.
- 문자 정확도는 NFKC/대소문자/공백·문장부호 제거 후 비교한다. CER은 전체 문자 편집거리 합 /
  정답 문자 수 합이다. 최종 명령 정확도와 구분한다. 같은 27개를 두 번 돌린 54회이며
  독립 발화 54개나 다른 화자에 대한 정확도가 아니다.
- 측정 중 짧은 소스 검사·단위 테스트도 수행했다. 전용 무부하 벤치마크가 아니므로
  중앙값의 수십 ms 차이는 의미 있는 개선으로 해석하지 않고, 긴 재시도 지연과 판정 결과를 본다.
- STT 시간은 실제 segment 소비까지 포함한다. VAD 종료 대기 0.9초, 대기열, LLM, ROS,
  물리적 정지는 포함하지 않는다. CPU 상황에 따라 바뀌며 작은 차이를 성능 개선으로 단정하지 않는다.
- LLM은 STT 비교 후 별도 워밍업하며 같은 전사문 결과를 캐시한다. 이 결과로 LLM의 지연이나
  반복 안정성을 주장하지 않는다. 최종 명령은 실제 로컬 분류 결과지만 ROS 발행/상태 게이트는 제외한다.
- 합성 무음은 실제 방의 잡음이나 다른 사람 음성 전체를 대표하지 않는다. 이 무음은 VAD를 우회해
  STT에 직접 넣은 대조군이다. 따라서 무음 오전사 횟수를 실제 로봇의 오발행 횟수로 해석하지 않는다.


모델 환경: faster-whisper `1.2.1`, CTranslate2 `4.8.5`.
LLM에 전달하는 SYSTEM_PROMPT SHA256(끝 개행 제거): `b184e9bc9b5c26ef822a79d2d18025aaecbde07f014325f2515817b653ff8df6`.

## VAD 관찰과 남은 문제

저장된 WAV를 새 WebRTC VAD로 재생했을 때 27개 모두 시작 조건을 통과했다.
15번 “스톱”과 18번 “잠깐 스톱”은 300ms 창 안 RMS까지 통과한 음성 프레임 최대가 7개였다.
현재 시작 기준은 6/10개, 즉 300ms 안에 180ms 상당의 통과 프레임이다. 짧거나 약한
“스톱”이 이 조건에 못 미칠 가능성은 있지만, 실패한 실제 음성이 없어 원인을 확정하지 않는다.
각 WAV의 앞부분에서 VAD 상태를 새로 시작하므로 이 재생은 상시 스트림의 판정을 그대로
복제하지 않는다. 16번의 종료 전환이 재생에서 안 나온 것도 이전 스트림 상태 차이를 보여준다.
VAD mode/RMS/시작 비율/종료 무음은 이번에 변경하지 않았다.

## 구현·검증과 원시 자료

- `stt_config.py`: beam, 문자열 힌트, 재시도 온도 목록 검증 및 decoder 인자 생성.
- `parameters.py`, YAML, pipeline: 실행 설정 연결, `[STT READY]`에 실제 설정 표시.
- `compare_stt_settings.py`: 원본 해시·정답 검증, 같은 PCM 비교, 문자/정지/명령/무음 분리 집계.
- `inspect_vad_audio.py`: 마이크 접근 없이 WAV의 모든 프레임 RMS·VAD·시작 조건·전환 기록.
- `colcon build --symlink-install --packages-up-to voice_command_pkg`: 2개 패키지 성공.

## 노트북: 새 설정 확인

```bash
cd ~/2026project
source voice_env.sh
STT_CHECK_DIR=$(mktemp -d "$PWD/recordings/stt_check.XXXXXX")
echo "결과 위치: $STT_CHECK_DIR"
ros2 run voice_command_pkg voice_command_node --ros-args \
  --params-file "$PWD/src/voice_command_pkg/config/voice_command.yaml" \
  -p publish_commands:=false -p save_recordings:=true \
  -p recordings_dir:="$STT_CHECK_DIR" \
  2>&1 | tee "$STT_CHECK_DIR/session.log"
```

`[LISTENING]` 이후 “바세린 가져다줘”, “스톱”, “잠깐 스톱”, “멈춰”, “안녕하세요”를
하나씩 말하고 각 결과를 기다린다. Ctrl+C 후 같은 터미널에서:

```bash
rg '\[(STT READY|VOICE START|STT|COMMAND|TIME|ERROR)\]' "$STT_CHECK_DIR/session.log"
```

`publish_commands=false`이므로 로봇 명령을 보내지 않는다. Jetson이 꺼져 있으면 일반
요청이 `robot_unknown`으로 폐기되는 것은 정상이며, 전사문은 `[STT]`에서 확인한다.
정지는 `by=rule:...`, `llm=0.000s`, `[ROS] skipped`여야 한다.

## 노트북: 빠른 스톱의 누락 원인에 필요한 연속 녹음

위 노드를 Ctrl+C로 종료한 다음 실행한다. 이 녹음은 VAD를 통과하지 못한 구간도 보존하며,
ROS와 연결하지 않는다. 첫 5초는 조용히 있고, 평소 속도 “스톱” 3번 → 천천히 “스-톱”
3번 → “멈춰” 3번을 각각 약 3초 간격으로 말한다. 남은 시간은 조용히 기다린다.
50초 후 자동 종료한다.

```bash
cd ~/2026project
STOP_PROBE_DIR=$(mktemp -d "$PWD/recordings/stop_probe.XXXXXX")
echo "연속 녹음 위치: $STOP_PROBE_DIR"
arecord -D pulse -f S16_LE -r 16000 -c 1 -d 50 "$STOP_PROBE_DIR/continuous.wav"
PYTHONPATH=src/voice_command_pkg .venv/bin/python \
  tools/voice_eval/inspect_vad_audio.py "$STOP_PROBE_DIR/continuous.wav" \
  --output "$STOP_PROBE_DIR/vad.json"
echo "분석할 위치: $STOP_PROBE_DIR"
```

`continuous.wav`와 `vad.json`이 있으면 된다. 녹음 경로와 아홉 번의 발화 중 실수한 순서가
있었는지만 알려주면 된다. 실제 음성 구간과 VAD start를 대조하고, 누락된 구간을 따로
전사하여 녹음 시작 실패인지 STT 오인식인지 분리한다. 정상 판정은 자연스럽게 말한
3번 모두 별도 발화로 잡히는 것이며, 조용한 구간에서는 불필요한 시작이 없어야 한다.
