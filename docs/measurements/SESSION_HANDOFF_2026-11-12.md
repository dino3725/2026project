# Jetson 작업 종료·재개 기록 — 2026-11-12

사용자 요청: 오늘 진행한 내용을 커밋하고 GitHub에 푸시한 뒤 마무리.
작업 브랜치는 `jetson/development`이며 `main`에 병합하거나 푸시하지 않는다.

## 저장한 작업

1. ChArUco 촬영·내부 파라미터 검증·장착 보정 도구와 기존 미커밋 수치 자료.
2. 관절별 잔차·추정 가능성 진단. 모든 관절 영점과 카메라 장착을 동시에 확정할 수 없는 관계 확인.
3. 고정 팔 모델과 기존 RGB-D를 이용한 6개 방식 비교, 자세 그룹 교차검증과 후보 선정.
4. 사용자가 선정한 `factory_rgbd_5mm` 후보를 `jetson_rgbd_20261112_v1`으로 채택.
5. 두 vision launch의 공통 카메라 설정, 하드웨어·MoveIt의 동일한 +25mm 팔 받침 모델 실행 경로.
6. 짧은 실물 시험: 인식 자세 1회, 콜라 인식 3/3회, RGB-D 10쌍과 실제 설정 확인.

현재 보정값은 `src/vision_pkg/config/camera_mount.yaml`에 있다.
실물 시험 결과와 좌표 기준은 [시험 보고서](accepted_calibration_test_2026-11-12.md)를 따른다.
상자 윗면 계산 높이는 67.61mm로, 사용자 제공 80mm보다 **12.39mm 낮다**.
실제 파지 시험은 하지 않았으며, 보정값 채택이 절대 정확도 검증 완료를 뜻하지 않는다.

## 종료 상태

- 측정 제어기에 `stop`을 전달한 뒤 현재 자세 유지·작업 취소 경로를 거쳤다.
- 측정 제어기, vision2·손바닥·카메라 장착 TF, RealSense를 종료했다.
- 조이스틱 상위 실행기는 첫 SIGINT만으로 종료되지 않아 하위 joy 드라이버에 SIGINT를 전달하고
  상위 실행기도 종료된 것을 확인했다.
- 하드웨어 launch를 마지막으로 종료했다. controller_manager, robot_state_publisher, 라이다도
  종료됐으며 해당 실험 프로세스가 남아 있지 않음을 확인했다.
- 자동 HOME·그리퍼 열기/닫기·새 이동은 요청하지 않았다. 종료 후 팔 자세가 유지된다고 보증하지 않는다.
- Jetson 운영체제를 종료하거나 로봇의 물리 전원 스위치를 조작한 것은 아니다.

종료 감사 기록: [shutdown.json](data/2026-11-12/accepted_calibration_test/shutdown.json).

## 검증·백업

- 보정 도구 전체 테스트: **70개 통과**.
- `vision_pkg`: **18개 통과, 기존 copyright 테스트 1개 skip**. 빌드 및 flake8·pep257 통과.
- 원본 RGB·깊이 영상과 런타임 로그는 `log/` 및 로컬 `log/backups/`에만 보관한다.
- 저장소에는 코드·설정·수치 JSON/CSV·보고서·출력용 표식판과 결과 그래프만 포함한다.
- 주요 원본 백업: `accepted_calibration_test_20261112.tar.gz`, `rgbd_refinement_20261112.tar.gz`,
  `pose_residual_diagnosis_20261112.tar.gz`, 두 hand-eye 세션 및 내부 파라미터 촬영 백업.
- 종료 후 업데이트는 `log/backups/session_close_20261112.tar.gz`에 추가 보관한다.
  기존 실험 원본·결과 백업은 덮어쓰지 않는다.
- 이전 `files_sha256.json`들은 각 실험 당시의 스냅샷이며, 이후 갱신된 문서의 현재 해시와 다를 수 있다.
- 수치 CSV는 원본 해시를 보존하도록 CRLF 바이트를 유지한다. `.gitattributes`에서 해당
  CSV의 자동 줄바꿈 변환을 끄고, 공백 검사에서도 CRLF를 정상 줄바꿈으로 처리한다.

## 다음 재개

1. 현재 팔 자세·카메라 장착·상자 배치를 새로 확인한다. 종료 전 배치를 자동으로 가정하지 않는다.
2. 하드웨어는 `eated_hardware.sh`, MoveIt이 필요할 때는 `eated_moveit.sh`를 사용한다.
   두 스크립트는 동일한 보정 모델을 검증한다. 공식 vendor launch를 직접 섞어 실행하지 않는다.
3. 좌표 시험 재개는 `measurement_control.py`로 진행하고 새 Y 입력을 확인한다.
   일반 control launch는 시작 시 HOME으로 움직이므로 단순 좌표 확인에 사용하지 않는다.
4. 남은 높이 차이와 깊이 유효성을 먼저 확인한다. 높이에 12mm를 일괄 더하는 보정은 아직 없다.
5. 실제 접근·파지 시험은 주변 정리와 정지 입력을 확인한 뒤 별도 단계로 진행한다.

다른 컴퓨터에서 이 브랜치를 사용할 때는 먼저 해당 컴퓨터의 미커밋 변경을 확인하고 동기화한다.
이 브랜치에는 Jetson 설정이 포함된다. 노트북의 음성 개발 브랜치에 임의로 덮어쓰지 않는다.
