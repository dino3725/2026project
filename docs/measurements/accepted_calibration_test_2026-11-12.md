# 채택 보정값 적용과 짧은 실물 좌표 시험 — 2026-11-12

> 이후 사용자의 작업 마무리 요청으로 실험 프로세스를 모두 종료했다.
> [종료·재개 기록](SESSION_HANDOFF_2026-11-12.md). 아래 시험 직후의 실행 상태와 구분한다.

**사용자 요청에 따라 `factory_rgbd_5mm` 후보를 사용할 보정값 v1으로 채택·저장하고 실제 TF에
적용했다. 콜라 인식 3/3회와 설정 일치를 확인했지만, 상자 높이는 약 12mm 낮게 계산됐다.**
사용할 값의 선정과 실제 절대 정확도의 검증 완료는 구분한다. 이전 분석에서 자동 적용을
보류했던 후보를 사용자가 명시적으로 선택한 것이며, 과거 후보 파일은 원래 상태로 보존했다.

## 채택한 값과 실행 경로

| roll | −0.019564244682444217rad |

값의 자릿수는 계산값 보존을 위한 것이며 그 정밀도의 실측 정확도를 뜻하지 않는다.
카메라 내부값은 기존 공장값, 깊이 스케일은 기존 설정을 유지한다.
카메라 optical frame으로의 별도 변환은 RealSense가 발행하며 위 표는 카메라 본체 프레임 기준이다.

- `vision.launch.py`, `vision2.launch.py`는 같은 YAML을 기본값으로 읽는다. 기존 개별 launch
  인수 재정의 기능은 유지한다. 잘못된 프레임·비유한 좌표는 시작 전에 거부한다.
- `eated_hardware.sh`는 보정에 사용한 팔 받침 +25mm 모델을 검증하고 실행한다.
  `base_link→link1` z는 0.116m다. 출력 좌표에 +25mm를 다시 더하지 않는다.
- `eated_moveit.sh`와 2번 실행 창도 같은 모델을 사용하도록 연결했다. 이번 좌표 시험에서는
  MoveIt을 실행하지 않았고 팔 이동은 기존 관절 인식 자세 한 번만 수행했다.
- `ensure_calibrated_model.py`는 생성 모델이 없으면 준비하고, 기존 모델이면 vendor 소스 해시,
  생성 launch 내용, URDF 해시, 채택 보정값이 요구하는 모델 해시를 확인한다.
- 직접 공식 vendor launch를 호출하면 이전 팔 받침 높이가 사용될 수 있으므로 이후 실행은
  위 스크립트·실행 창을 사용한다. 팔 속도·가속 배율, 자세, 그리퍼 값은 바꾸지 않았다.

## 이번 시험 절차와 확인

사용자는 카메라 장착 유지, 로봇·상자의 동일 지지면, 상자 위 콜라 준비를 확인했다.
카메라·F710·측정 전용 제어기를 시작하고 Y 입력을 확인했다. 첫 측정 제어기는 이동 요청 전
종료돼, 서비스 대기 요청을 취소했다. 그 요청으로 팔 이동은 실행되지 않았다. 원인은 확정하지
못했으며 로그 파일을 남기는 제어기로 재시작하고 Y 입력을 다시 확인했다.

하드웨어 활성화 후 기존 인식 자세 `[0, -30, -41, 115]°`로 1회 이동했다.
이후 팔을 고정하고 RGB-D 10쌍과 콜라 인식 3회를 수집했다. 집기·그리퍼 동작·비영 속도의
바퀴 명령은 보내지 않았다. 시험 종료 후 `stop`을 보내 `ERROR` 상태로 유지했으며 자동 HOME은 없다.

실행 중 TF에서 카메라 xyz·회전과 팔 받침 z=0.116m를 확인했다.
`robot_state_publisher`와 `controller_manager`의 전체 URDF 요소·속성·본문이 보정 모델과
일치했다. xacro CLI의 주석·포맷 때문에 원문 해시는 달랐으므로, 이를 모델 불일치로 숨기거나
단순 해시 일치로 보고하지 않고 XML 구조 전체 일치를 기록했다.
CameraInfo의 K/D도 선정 후보가 사용한 공장값과 정확히 일치했다.

## 상자·책상 영상 확인

10쌍의 RGB와 정렬 깊이 시각 차이는 모두 0ms였다. 현재 영상에서 미리 지정한 영역으로
깊이 점을 로봇 기준으로 변환했다. 아래 높이는 `base_link` 위 10mm를 더해 바퀴 지지면 기준이다.

| 영역 | 유효 프레임 | 계산 높이 평균 | 예상 기준 |
|---|---:|---:|---:|
| 먼 쪽 책상 | 10/10 | −1.85mm | 약 0mm |
| 왼쪽 책상 | 10/10 | −8.22mm | 약 0mm |
| 상자 윗면 오른쪽 | 10/10 | **67.61mm** | 사용자 제공 80mm |
| 상자 윗면 왼쪽 | 1/10 | 67.86mm | 사용자 제공 80mm |
| 상자 윗면 앞쪽 | 0/10 | 계산 제외 | 유효 깊이 부족 |

유효 깊이가 80% 미만인 영역은 제외하고 각 프레임의 유효 비율을 기록했다. 결과 높이를 보고
영역을 바꾸지는 않았다. 두 책상 영역을 하나의 평면으로 추정하는 조건은 3/10프레임만 통과했다.
그 일부 프레임의 상대 높이 90.9~94.5mm는 안정적이지 않아 상자 높이 검증 결과로 채택하지 않는다.
저장된 JSON에는 실패한 평면 추정과 유효 비율도 포함했다.

상자 오른쪽 윗면의 안정적으로 읽힌 값은 66.74~68.54mm이며, 사용자 제공 높이보다 평균
**12.39mm 낮다.** 이전 다른 장면에서 남았던 약 13mm의 차이가 이번에도 남았다.
카메라 보정값이 완전히 정확하다고 결론내리지 않으며, 높이 차이만큼 임의 오프셋을 추가하지 않았다.
