# 상자 표식판을 이용한 RGB 내부 파라미터 검증 — 2026-11-11

현재 상태: **계산용 15자세 + 별도 검증 5자세 촬영·비교 완료. 후보는 실제 설정에 적용하지 않음.**

## 실험 조건

- 기존 종이를 단단한 상자에 주름·들뜸 없이 붙였다는 사용자 확인 후 시작했다.
- 로봇 하드웨어·팔 제어기 없이 RealSense만 실행했다. 로봇 이동 명령은 보내지 않았다.
- 카메라는 고정하고 사용자가 표식판을 이동·회전했다. 수집기는 RGB/CameraInfo만 구독하므로
  카메라 고정 여부를 별도 센서로 검증한 것은 아니다.
- 컬러 1280×720, 기존 K/D는 이전 세션과 같음. 기존 fx=911.713, fy=911.495,
  cx=632.231, cy=372.981px, plumb_bob D=[0,0,0,0,0].
- 출력 무늬 실측 177×125mm를 반영했다. 설계는 175×125mm다. 축별 균일 인쇄 배율을
  가정하며 실측 불확도·종이의 미세한 비평면성은 별도로 정량화하지 못했다.
- 기존 K/D를 사용하지 않는 국소 호모그래피 방식으로 ChArUco 코너를 검출했다.
  [OpenCV 검출 설명](https://docs.opencv.org/4.5.0/df/d4a/tutorial_charuco_detection.html).
- 정면, 상하·좌우 기울기, 복합 기울기, 화면 좌우·상하 위치, 가까운/먼 거리와
  면내 90° 회전을 포함한다. 각 영상의 원본·코너·CameraInfo·해시를 보존했다.
- train_06, train_13은 20코너, train_11은 22코너, 나머지는 24코너다. 검출되지 않은
  점을 추측해서 채우지 않았다. 무늬가 모두 보이면 외곽 종이 여백의 잘림은 허용했다.

## 후보 계산

계산 전 15개 관측과 이미지·검토 기록 해시를 `training_frozen.json`으로 고정했다.
`solve_intrinsics.py`는 입력 해시, 동일 카메라·세션·실측 치수, 코너 ID와 물체점의 일치,
검토 통과 여부를 확인한다. audit/validation 입력을 fitting에 넘기면 거절한다.

[OpenCV calibrateCameraExtended](https://docs.opencv.org/4.5.4/d9/d0c/group__calib3d.html)를
사용한다. 보드 자세는 영상별로 추정하며 팔 모델이나 책상 높이를 입력하지 않는다.
아래 값은 **학습 관측 오차**이며 독립 검증 결과가 아니다. 픽셀 오차는 영상상의 잔차로,
밀리미터 깊이·카메라 장착 위치의 정확도를 입증하지 않는다.

| 방법 | 학습 재투영 RMS(px) | 코너 분할 RMS(px) | fx / fy(px) | cx / cy(px) |
|---|---:|---:|---|---|
| 기존 K/D | 0.3779 | 0.4224 | 911.71 / 911.49 | 632.23 / 372.98 |
| 초점거리·중심만 추정, 왜곡 0 | 0.3580 | 0.4023 | 942.53 / 939.14 | 624.13 / 406.75 |
| 방사 왜곡 k1,k2 포함 | 0.2928 | 0.3412 | 925.65 / 927.47 | 640.66 / 361.58 |
| 왜곡 5계수 진단 | 0.2874 | 0.3382 | 921.65 / 925.46 | 649.08 / 381.26 |

코너 분할은 체커 격자의 행·열 패리티로 두 집합을 만들고, 한쪽으로 보드 자세만 추정한 뒤
다른 쪽 코너를 예측하는 계산을 양방향 수행한다. 이 표에서는 K/D 자체는 전체 학습 영상으로
구했으므로 이것만으로 독립 검증이라고 부르지 않는다.

방사 왜곡 후보 D=[0.2217614, -0.3579172, 0, 0, 0]. 더 복잡한 5계수 후보의 개선은 작아
별도 검증의 주 비교 후보는 방사 왜곡 2계수 모델로 미리 지정했다. 후보 선택은 적용 승인이 아니다.

## 불안정성과 제한

각각 한 자세씩 빼고 다시 계산한 결과:

- 왜곡 0 후보 fx 약 932.00~962.11px, fy 약 928.23~957.80px.
- 방사 왜곡 후보 fx 약 906.44~944.33px, fy 약 907.98~946.79px.
- 방사 왜곡 후보의 내부 추정 표준편차 fx 약 13.56px, fy 약 13.81px.

잔차가 줄었지만 초점거리의 관측 선택 민감도가 남아 있다. 이 범위와 표준편차는 진단값이며
보증된 신뢰구간이 아니다. 공장 보정 오류가 확인됐거나 새 값이 더 정확하다고 아직 결론내리지 않는다.
이미지 가장자리 전체를 고르게 덮은 것도 아니므로 관측 밖 영역으로의 외삽에 주의한다.

RGB 후보를 적용하더라도 aligned depth가 기존 컬러 모델로 정렬된다면 일관성이 깨질 수 있다.
따라서 CameraInfo나 카메라 TF·깊이 스케일을 자동 변경하지 않는다.

## 별도 검증 완료 결과

후보와 평가 코드를 고정한 후 새 영상 5개를 수집했다. 모든 영상에서 24코너를 검출했으며,
후보 오차를 보지 않고 영상 품질·물리 표식 위치만 검토했다. 원본·관측·검토 해시를
`validation_frozen.json`에 고정한 뒤 `evaluate_intrinsics.py`로 평가했다.
학습 파일·후보·평가 코드의 해시와 입력 메타데이터를 대조했고 **K/D 재학습은 하지 않았다.**
각 검증 영상의 보드 자세만 해당 K/D로 추정했다.

| 방법 | 검증 재투영 RMS(px) | 검증 코너 분할 RMS(px) |
|---|---:|---:|
| 기존 K/D | 0.29519 | 0.33544 |
| 왜곡 0 후보 | 0.27968 | 0.31649 |
| 사전 지정한 방사 왜곡 2계수 후보 | 0.24257 | 0.28690 |
| 왜곡 5계수 진단 후보 | 0.25113 | 0.29955 |

주 비교 후보는 전체 잔차 약 **17.83%**, 코너 분할 잔차 약 **14.47%** 감소했다.

| 검증 영상 | 기존 RMS(px) | 방사 왜곡 후보 RMS(px) | 관측 위치 |
|---|---:|---:|---|
| validation_00 | 0.38772 | 0.28869 | 중앙, 복합 기울기 |
| validation_01 | 0.17440 | 0.26201 | 실제로는 중앙 아래 |
| validation_02 | 0.35176 | 0.24945 | 오른쪽 아래 |
| validation_03 | 0.21363 | 0.19748 | 중앙 위 |
| validation_04 | 0.29251 | 0.20242 | 가까운 중앙, 면내 회전 |

**5개 중 4개 개선, 1개 악화**이며 코너 분할 결과에서도 같은 방향이다.
validation_01은 왼쪽 아래를 요청했지만 실제 관측은 중앙 아래였다. 이를 왼쪽 관측으로
간주하지 않고 실제 위치를 기록했다. validation_03도 계획한 복합 기울기보다 단순한
기울기로 안내·수집했다. 검증은 전 화면을 균등하게 덮지 못했다.

사용자 요청으로 실시간 미리보기를 띄웠다. 모니터 일부가 원본 영상에 들어오지만, 각 검증의
검출 좌표가 모두 실제 상자의 표식에 속하는 것을 영상과 좌표 범위로 확인했다.
미리보기 프로세스가 한 번 종료되어 다시 시작했으며 RealSense는 계속 실행 중이었다.

판단: **내부 모델을 바꾸면 이 표식의 영상 일치도가 일부 개선되는 증거는 있지만,
실제 높이 오차의 원인을 확정하거나 후보를 운영 설정으로 채택하기에는 부족하다.**
초점거리 민감도와 표식 인쇄·평탄도 가정이 남는다. 기존 K/D, 카메라 TF, 깊이 스케일을 유지한다.
