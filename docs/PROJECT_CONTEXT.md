## 3. 시스템 구성 (현재)

```text
[노트북]
마이크 → WebRTC VAD → faster-whisper small (CPU int8, ko) → Ollama qwen3:4b-instruct (JSON)
      → 허용목록 검증 → /voice/robot_command (eated_interfaces/RobotCommand)
                                   │  Wi-Fi DDS
[Jetson]                           ▼
control_node (상태 머신)
  ├─ /find_object (FindObject 액션) → vision_node2: YOLO best.pt + aligned depth → base_link 좌표
  ├─ /vision/open_palm ← hand_gesture_node: MediaPipe, DRIVE_TO_PLACE에서만 동작
  ├─ /joy ← joy_node (F710: A 재시도, X HOME 복구, Y 비상정지)
  ├─ /move_action, /compute_cartesian_path, /execute_trajectory (MoveIt 2)
  ├─ /arm_controller/follow_joint_trajectory, /gripper_controller/gripper_cmd
  ├─ 발행: /control/state, /control/command_status, /control/target_class,
  │       /control/manual_drive_enabled, /control/release_countdown_sec
  └─ /cmd_vel (안전 루프의 0 속도) ── total_control도 /cmd_vel 발행
```

### 상태 머신 (control_pkg/task_state.py)

```text
IDLE → MOVE_TO_RECOGNITION → VISION_SEARCH → PICKING → MOVE_TO_CARGO
     → DRIVE_TO_PLACE (수동 주행) → [손바닥 2초] → PLACING → RETURN_HOME → IDLE
```

- 일반 실패: `ERROR` → 자동 HOME → `IDLE`. HOME도 실패하면 `ERROR`에 머물고 X로 재시도합니다.
- Y 버튼 또는 음성 stop: 모든 액션 취소, 팔 hold, `ERROR` 유지. X를 눌러야 복구됩니다.
- 수동 주행 허용 상태: `IDLE`, `DRIVE_TO_PLACE`, `ERROR`.

### Pick 동작 순서 (control_node `_recognition_pick_sequence`)

1. RECOGNITION 자세로 관절 이동, 0.5초 대기
2. `FindObject` 요청: 2초 이상 안정 감지와 샘플 10개 이상이면 base_link 좌표의 중앙값을 반환
3. 파지점 = 검출 좌표 + (0.02, 0, 0) — 항상 base_link 정면(x) 방향
4. 그리퍼 열기 → MoveIt으로 파지점 5 cm 위(PREGRASP) → 5 cm 하강(PICK)
5. 그리퍼 닫기: 중간에 멈추고(stall) 위치가 임계값 이상이면 파지 성공, 끝까지 닫히면 실패
6. 수직 상승(RETREAT, 최대 15 cm). 계획이 안 되면 가능한 만큼 또는 건너뜀
7. CARGO 자세로 관절 이동 → `DRIVE_TO_PLACE`

- 정해진 자세(HOME/RECOGNITION/CARGO)는 관절 각도로 바로 보내며, 충돌 검사를 하지 않습니다.
- 4축 팔이라 position-only IK입니다(손 방향은 지정하지 않음).

### 메시지

- `RobotCommand`: `header`, `action`(fetch/stop/unknown), `target_class`, `transcript`
- `RobotCommandStatus`: `header`, `accepted`, `action`, `target_class`, `message`
- `FindObject`: goal `target_class` / result `success, x, y, z, confidence, frame_id, message` / feedback `detected, stable_time, confidence`

### 주요 파라미터 (현재값)

- **VAD:** mode 3, 30 ms 프레임, 시작 창 300 ms 중 60%, 시작 RMS 200, 종료 무음 900 ms, pre-roll 450 ms, 최대 15초, 상시 스트림 시작 시 1회 1.2초 버림
- **LLM:** `think: false`, `temperature: 0`, `seed: 0`, `num_predict: 32`, `keep_alive: 10m`, 타임아웃 120초
- **비전:** conf 0.5, 안정 감지 누적 2.0초, 최소 샘플 10, 인식 타임아웃 10초, 깊이 창 7, 최대 10 Hz, 프레임 나이 0.5초 이내
- **Pick:** 보정 (0.02, 0, 0), PREGRASP +5 cm, RETREAT 최대 15 cm, MoveIt 속도·가속 배율 0.10, 위치 허용 오차 1 cm 상자, 그리퍼 힘 0.2
- **카메라:** eye-in-hand. `end_effector_link` → `d435i_link` = (−0.065, 0.0195, 0.052), 각도 모두 0 (실측 보정 전)
- **조이스틱:** 최대 0.20 m/s, 0.60 rad/s, 50 Hz 발행, 중립 복귀 필요
- **YOLO `best.pt`:** YOLO11n, Ultralytics 8.4.152, 클래스 airpod/coke/tissue/vaseline
  - 테스트 151장 기준 mAP50 0.949, mAP50-95 0.823
  - vaseline mAP50 0.855 / 재현율 0.857, coke 재현율 0.839
  - 알려진 오인식: airpod→tissue, vaseline→airpod

## 4. 분석에서 나온 문제 (중요도 순)

1. **음성 stop이 느리고 유실될 수 있습니다.**
   - 전사문 stop은 VAD 종료 대기 0.9초 + Whisper를 거치며 LLM은 건너뜁니다. 일반 명령은 LLM을 사용합니다. LLM은 웜 2.5~3.5초, 콜드 52.8초(옛 분류기 측정값)입니다.
   - `keep_alive: 10m`라서 10분 넘게 쉬면 모델이 내려가고, 시작 시 워밍업 호출도 없습니다.
   - 11/10 상시 녹음으로 처리 중에도 입력을 수집합니다. 다만 순차 STT/LLM 대기와 대기열 과부하 시 미전사 발화 제거로 stop이 늦거나 유실될 가능성은 남습니다.
2. **화자를 구분하지 않습니다.** 옆 사람의 말도 명령으로 받아들입니다.
3. **stop 이후에는 음성만으로 복구할 수 없습니다.** 음성 stop은 어떤 상태에서든 `ERROR`로 가고, 복구는 X 버튼으로만 됩니다.
4. **사용자 피드백이 없습니다.** 음성 쪽이 `/control/command_status`와 `/control/state`를 구독하지 않습니다. `command_status`는 수락 시점에만 발행됩니다.
5. **Pick 좌표 정확도가 검증된 적 없습니다.**
   - 카메라 장착값은 자로 잰 값입니다. 각도 1° 오차는 30 cm 앞에서 약 5 mm 오차가 됩니다.
   - 파지 보정이 네 물체 모두 같은 2 cm이고, 물체가 옆에 있어도 정면 방향으로 더해집니다.
   - 팔 자체의 위치 오차, 깊이 측정 흔들림, 인식 자세의 적합성도 측정된 적이 없습니다.
6. **도달 가능성 판단과 재시도가 없습니다.** 비전 좌표를 확인 없이 MoveIt에 넘기고, 범위 밖이면 실패 → HOME으로 끝납니다. 지금은 사람이 로봇을 물체 앞에 놓아줘서 동작합니다.
7. **`/cmd_vel` 경합이 있습니다.** 수동 주행 권한이 꺼지면 `total_control`(50 Hz)과 `control_node` 안전 루프(20 Hz)가 0 속도를 계속 발행합니다. 이대로 Nav2를 붙이면 Nav2의 속도 명령이 덮어써집니다.
8. **팔 복귀 경로에 충돌 검사가 없습니다.** RETREAT 실패 시 상승 없이 CARGO로, 실패 시 자동 HOME과 X 복구도 관절공간으로 직행합니다. (이번 학기 개선 범위에서 제외, 5.5 참고)
9. **현재 6분류의 평가가 부족합니다.** 엄밀한 held-out(160문장, 92.5%)은 옛 클래스 기준입니다. 현재는 텍스트 64문장 회귀뿐이고, stop 17문장 중 10개가 프롬프트에 그대로 있습니다.
10. **위생 문제:** `/home/sh/...` 경로 하드코딩(음성 README), LICENSE 없음(Ultralytics는 AGPL-3.0), 음성 README의 오래된 문장. (`ROS_DOMAIN_ID`와 Jetson 경로는 해결됨)

### 좋은 점 (유지할 것)

- `operation_id` 기반 작업 무효화, 액션 목표 일괄 취소
- 버튼 상승 에지 판정, `TRANSIENT_LOCAL` 주행 권한 전달, 스틱 중립 요구

## 5. 이번 학기 개발 계획 (확정)

### 5.1 VAD — 노트북

| 번호 | 항목 | 내용 |
|---|---|---|
| ① | 상시 녹음 | 녹음 스레드(스트림 1회 오픈, 상시 청취)와 처리 스레드를 큐로 분리. 1.2초 버리기는 시작 시 1회만 |
| ② | 종료 대기 조정 | 종료 무음 900 ms를 500~600 ms로 낮춰 보고, 말 잘림과 지연을 실측해 결정 |
| ③ | 화자 인증 | 등록된 내 목소리의 fetch만 받음. **stop은 화자와 무관하게 항상 받음** |

화자 인증 설계:
- 등록: 내 목소리로 명령 문장 20~30개를 녹음 → 화자 임베딩 평균을 기준값으로 저장
- 판정: 매 발화의 임베딩과 기준값의 코사인 유사도 ≥ 임계값
- 모델 후보: SpeechBrain ECAPA-TDNN, Resemblyzer. CPU 지연을 1주차에 실측해 선택
- STT와 병렬로 실행해 체감 지연을 늘리지 않음
- stop을 예외로 두는 이유: 위급할 때 옆 사람도 멈출 수 있어야 하고, 0.5초짜리 짧은 발화는 화자 인증 정확도가 낮음
- 등록 환경과 시연 환경의 마이크·울림 차이에 주의. 시연 장소에서 재등록하거나 여러 환경 녹음을 섞음
- 타인 음성 평가 데이터는 동의를 받고 녹음
- 지표: FRR(내 목소리 거부율), FAR(타인 수락률), 임계값별 곡선

제외: wake word (화자 인증으로 대체)

### 5.2 STT — 노트북

| 번호 | 항목 | 내용 |
|---|---|---|
| ① | 메모리 직접 전사 | WAV 파일 없이 오디오 배열을 바로 전사. 녹음 저장은 평가 데이터 수집용 옵션 |
| ② | 로봇 어휘 힌트 | `initial_prompt`(지원 시 `hotwords`)에 콜라, 바세린, 휴지, 에어팟, 멈춰, 정지 |
| ③ | 속도·정확도 비교표 | 모델 크기(small, base 등) × `beam_size`별 발화당 시간과 인식률 |
| ④ | 전사문 정규화 | 공백 제거, "멈쳐"/"멈처" 같은 흔한 오인식 흡수. 5.3의 정지 키워드 판정이 사용 |
| ⑤ | 정지 전용 키워드 감지 | "멈춰/정지/스톱"을 오디오에서 바로 잡는 경량 키워드 감지. Whisper를 기다리지 않고 즉시 stop |

- ⑤는 ①~④와 종단 지연 측정 이후에 붙여, 전후 지연을 비교합니다.
- 정지 판정은 세 겹입니다: ⑤ 전용 감지 → ④ 정규화한 전사문 키워드. LLM은 정지 판단에 쓰지 않습니다.

### 5.3 LLM — 노트북

| 번호 | 항목 | 내용 |
|---|---|---|
| ① | 정지 판단에서 LLM 제외 | 정지는 5.2에서 처리. LLM은 fetch(물체 4종)와 unknown만 판단 |
| ② | 상시 로드와 워밍업 | `keep_alive: -1`, 시작 시 더미 문장 1회 분류 |
| ③ | 타임아웃과 실패 처리 | 120초 → 약 10초. 실패하면 "다시 말씀해 주세요" 안내 |
| ④ | 실제 녹음 재평가 | 본인 녹음을 STT에 통과시킨 결과로 평가셋 구성. 동결 → SHA256 → 1회 실행 |

- 녹음은 5.1 화자 인증, 5.2 비교표, 5.3 재평가에 함께 쓰이도록 한 번에 모읍니다.
- 이유: stop 미탐은 위험하고 fetch 오탐은 불편한 정도라서, stop은 규칙으로, fetch는 LLM으로 처리합니다.

제외: 되묻기(다중·애매 요청 대화), 작은 모델 비교, LLM으로 응답 문장 생성

### 5.5 매니퓰레이터 — Jetson

원칙: **먼저 재고, 좌표 사슬의 앞에서부터 고친다.** 물체별 보정값은 앞 단계 오차까지 흡수하므로, 앞 단계를 먼저 고쳐야 다시 맞출 일이 없습니다.

오차 예산: 카메라 보정 + 깊이 측정 + 팔 위치 + 보정값 오차의 합 < 그리퍼 여유 폭(최대 폭 − 물체 폭)

진행 순서 (번호는 원래 목록 번호):

| 순서 | 번호 | 항목 | 내용 |
|---|---|---|---|
| 1 | 1 | 오차 기준선 측정 | 그리퍼 최대 폭·물체 폭, 비전 좌표 vs 실측 위치, 팔 목표 vs 실제 도착 위치 |
| 2 | 2 | 카메라 장착 보정 | 체커보드·마커 등으로 `end_effector_link`→`d435i_link` 변환 정밀 보정, 특히 각도 |
| 3 | 3 | 팔 정확도 확인·보정 | 관절 영점, 뻗었을 때 처짐 확인. 큰 오차가 있으면 보정 |
| 4 | 4 | 인식 자세 최적화 | 카메라-물체 거리와 내려다보는 각도를 바꿔 오차가 가장 작은 자세 선정 |
| 5 | 5 | 깊이 측정 안정화 | 물체별 깊이 흔들림 측정, 반짝이는 물체는 측정 영역 조정 |
| 6 | 7 | 보정 방향 수정 | "정면(x)으로 2 cm" → "로봇에서 물체를 향하는 방향으로" |
| 7 | 8 | 물체별 파지 보정 | 물체마다 잡는 깊이·높이 값을 실험으로 결정, 파라미터화 |
| 8 | 10 | 도달 가능성 판정 | MoveIt 호출 전 거리·높이로 1차 판정, 애매하면 `plan_only`. 범위 밖이면 5.6 베이스 정렬 요청 |
| 9 | 12 | 실패 시 1회 재시도 | 파지 실패 시 재인식 후 한 번 더 시도 |

- 도달 판정, 보정 방향, 정렬량 계산은 ROS에 의존하지 않는 순수 함수로 분리해 pytest로 테스트합니다.

제외: 6 인식 안정성(오인식·중복 물체), 9 그리퍼 힘·미끄러짐, 11 안전한 복귀 경로(충돌 회피 복귀)

11번을 제외했으므로 실험과 시연에서 다음을 지킵니다:
- 팔 속도·가속 배율 0.10 유지
- 조이스틱을 손에 들고 Y 버튼을 누를 준비
- 책상 위에는 실험 물체만 둠

### 5.6 자율주행 — Jetson

| 번호 | 항목 | 내용 |
|---|---|---|
| 1 | 지도 작성 | `turtlebot3_manipulation_cartographer`로 지도 작성, 이름 붙인 위치(픽업/전달/대기). 제공 패키지 |
| 2 | Nav2 단독 주행 | `turtlebot3_manipulation_navigation2`로 이름 붙인 위치까지 주행 확인. 제공 패키지 |
| 3 | 주행 권한 정리 | `twist_mux` 우선순위: 비상정지 잠금 > 조이스틱 > Nav2. `total_control`·`control_node`의 0 속도 연속 발행 방식 변경 |
| 4 | 상태 머신 연동 | `DRIVE_TO_PLACE`에서 `NavigateToPose`로 전달 지점 자동 이동. 목표는 `_send_goal`로 `_active_goals`에 등록되어 비상정지 시 취소. Nav2 실패 시 수동 주행으로 전환 |
| 5 | 이동 조작 조건 | 팔 자세(HOME/CARGO, CARGO는 1번 관절 −73°)별 footprint, 물건을 들었을 때 속도·가속 제한 |
| 6 | 베이스 정렬 | 5.5 도달 판정이 범위 밖이라고 하면 회전각 atan2(y, x)와 전진 거리를 계산해 오도메트리로 저속 이동 후 재인식(최대 2회) |
| 7 | 대기 위치 자동 복귀 | 놓기 후 HOME 자세로 돌아오며 대기 위치까지 자율 이동 (4 이후) |
| 8 | 픽업 위치까지 자율 이동 | 명령을 받으면 물건이 있는 위치까지 먼저 자율 이동한 뒤 인식 시작. 도착 위치가 매번 달라 6이 중요해짐 |

- Nav2 기본 도착 허용 오차(약 25 cm)가 팔 작업 범위보다 커서 6이 필요합니다.
- 1·2는 공개 패키지를 쓴 기반으로 명시합니다. 본인 기여는 3·4·5·6·7·8과 5.5의 도달 판정입니다.

제외: 9 음성으로 목적지 지정

## 9. 최종 시연 시나리오

1. **전체 흐름:** "목마른데 마실 거 가져다줘" → 화면에 "콜라 가져올게요" → 물건 위치로 자율 이동 → 인식, 필요하면 정렬 → Pick → 사용자에게 자율 이동 → 손바닥 → 놓기 → 대기 위치 복귀
